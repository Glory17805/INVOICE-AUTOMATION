01 Data and correctness

The workbook is the system of record. These are the ways it, or the trail proving it, could be lost or wrong.

D1Nothing backs up the data directory

Blocker

backend/data/ holds the per-period workbooks, the SQLite queue, and archive/ — the archived originals that are the audit trail for every posted row. It is gitignored, correctly, and nothing copies it anywhere.

The master workbook can re-seed structure. It cannot re-seed posted rows, and nothing can re-seed the archived PDFs. A disk failure, a bad Reset, or a stray rm takes the filing evidence with it.

Fix A scheduled copy of data/workbook/ and data/archive/ to anywhere else. Half an hour of work; the cheapest item on this list by a wide margin.

D2Money crosses the wire as floating point

High

Internally the tax arithmetic uses Decimal and is correct. But every amount entering and leaving the API is a float — the extraction schema, the JSON responses, and the values written into the workbook.

app/models.pytaxable_value: Optional[float] cgst_amount: Optional[float] igst_amount: Optional[float]

Binary floating point cannot represent 0.1 exactly. Today the quantisation to two decimals hides it. At scale, in a system whose whole job is producing figures that reconcile to the rupee, this is the wrong representation to be carrying.

Fix Strings or integer paise on the wire, Decimal throughout. Contained but touches the schema, so it wants doing before there is a second consumer of this API.

D3One writer, enforced but not solved

Medium

A second backend against the same data directory refuses to start, and that guard has already fired twice in practice. But it converts a corruption risk into an availability limit rather than removing it: this cannot serve two concurrent users safely, and --workers is permanently off the table.

Fix Move workbook writes behind a single queue consumer. Not needed yet. The constraint should be understood before anyone reaches for more processes.

D4The activity log grows without limit

Low

sessions and password_resets are purged at startup. activity never is — by design, it is an audit trail. But an audit trail with no retention policy is one nobody has decided about, and it shares a database with the working queue.

Fix Decide a retention period, export older entries, prune. A compliance decision more than a technical one.

D5openpyxl does not round-trip charts or pivot tables

Low

Reading and re-saving the workbook preserves formulas and values, not charts or pivots. The May-26 workbook has neither, so nothing is lost today. It would be lost silently the first time someone adds one.

02 The API

35 endpoints, all reachable, all guarded. The gaps are in shape rather than in coverage.

A1Every response is an untyped dictionary

High
measuredresponse_model= declarations : 0 handlers returning bare dict : 35

FastAPI generates its schema from return types. With every handler annotated -> dict, /openapi.json describes the paths and the query parameters but says nothing about what comes back. The generated docs are half a contract.

This is not theoretical: a change to /api/documents shipped a response shape the page could not consume, and the failure surfaced as state.documents is not iterable in a user's browser. Response models would have made that a schema change rather than a surprise.

Fix Pydantic response models on each route. Mechanical, and it makes the interactive docs genuinely usable.

A2The whole queue is loaded and parsed on most requests

High
measured against a real 357-document queue357 documents, 0.7 MB of JSON, parsed in 39 ms call sites of store.all_documents() : 9 extrapolated to 5,000 documents : ~553 ms per call

/api/info, /api/dashboard, /api/documents, /api/admin/stats, the duplicate hash check and the queue-twin check all call store.all_documents(), which reads and JSON-decodes every row. Loading the Dashboard does it more than once. Uploading does it per file, then again per invoice read.

A single client filing a few hundred invoices a month reaches thousands of rows within a year, at which point every screen carries a half-second of avoidable work.

Fix Push filtering and counting into SQL. The indexes on status and period already exist and are unused by these paths.

A3No real pagination

Medium

/api/documents takes limit (capped at 1000) and no offset or cursor. Past a thousand documents the History screen simply cannot reach the rest, and nothing in the response says so — total and the returned count just disagree.

Fix Cursor pagination on received_at, and a has_more flag the page can act on.

A4No API version in the path

Medium

Routes are /api/…. There is one consumer today, so breaking changes are survivable — but the shape has already broken once, and the next consumer will be somebody's script.

Fix /api/v1/ now, while it costs a search and replace.

A5No global exception handler and no request logging

Medium
measuredexception_handler registrations : 0 log statements in main.py : 5 (all at startup)

An unhandled exception returns FastAPI's default 500 with no correlation id, and the traceback goes to a console nobody is reading. There is no way to connect a user saying "it broke" to the event that broke.

Fix A handler that logs with a request id and returns that id to the caller. Structured logging so the output is greppable.

A6Background work is fire-and-forget

Medium

Reading happens in a FastAPI BackgroundTask. If the process restarts mid-batch, those documents stay at new for ever — nothing retries them and nothing notices. The Processing screen would poll a stage that never advances until its own fifteen-minute ceiling.

Fix Re-queue anything left in new at startup. Small, and it closes the whole failure mode.

03 Security and access

Authentication is real and reasonably built. What surrounds it is not yet finished.

S1Client invoices may be training a third-party model

Blocker

Extraction runs on Gemini's free tier, where Google may use inputs to improve their models. The inputs here are a real company's invoices: named counterparties, GSTINs, amounts, addresses.

The application warns about this on every screen and the warning cannot be dismissed, which is the right behaviour — but a warning is not a control.

Fix Enable billing on the key and set GST_GEMINI_TIER=paid, or supply a funded Anthropic key and switch provider. A one-line change either way; the decision is commercial, not technical.

S2No TLS

Blocker

Session tokens travel in an Authorization header on every request, and invoices travel in responses, all in clear text. On one machine that is fine. The moment this is reachable across a network it is a credential and a document set on the wire.

Fix Terminate TLS at a reverse proxy. Do not attempt it in the application.

S3Signup is currently open to anyone who reaches the page

Blocker
live, at time of writingGET /api/bootstrap -> {"signup_mode": "open", ...}

The setting ships as approval, where an administrator lets people in. It is currently open: anyone who can load the sign-in page can create a working account and read every invoice, every register and the whole workbook, with nobody approving anything.

On localhost that is harmless. Combined with S2 it is the single most exposed thing here.

Fix Settings → Who can create an account → back to approval. One click.

S4No security headers on either server

High
measuredbackend : 0 references to CSP / X-Content-Type-Options / HSTS / X-Frame-Options frontend : 0 references

No Content-Security-Policy in particular. The session token lives in localStorage, so any successful script injection hands over an account. The page builds its DOM with textContent throughout, which is why no injection exists today — but that is a property of current code, not an enforced boundary.

Fix CSP, X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy. A dozen lines in the frontend handler.

S5Login throttling is in memory only

High
app/auth.py_attempts: dict[str, list[float]] = {}

Five failures start a backoff that doubles to fifteen minutes. It lives in a process dictionary, so a restart clears every counter — and the backend restarts often. Nothing else on the API is rate-limited at all.

Fix Persist the counters in the database, and add a blanket per-address limit in front of the whole API.

S6Uploads are trusted on their file extension

High

The only check is that the suffix is in a list. Nothing looks at the bytes. A file named .pdf containing anything at all is stored, handed to pypdf, and — for a real client — forwarded to a third-party model.

Fix Sniff the magic bytes and reject a mismatch. Consider a size-per-user quota; there is currently a per-file cap and no total.

S7Sessions never extend, and cannot be listed or revoked

Medium

Seven days from issue, fixed. Someone working daily is signed out mid-week with no warning. There is also no way to see your active sessions or end one on a device you no longer have — changing your password is the only lever, and it ends all of them.

Fix Slide the expiry on use, and a sessions list on the profile screen with a revoke button.

S8Secrets sit in plaintext

Medium

backend/.env holds the provider key and any service key, unencrypted, beside the code. Correctly gitignored. Acceptable on one trusted machine; not on a shared server.

S9Password reset depends on someone reading a log

Medium

No mail server is configured, so a reset link is written to the backend log and an administrator can generate one from the Admin screen. The security design is right — the anonymous route never returns the token, and answers identically for unknown addresses. The delivery is a manual step nobody will remember at the moment they need it.

Fix SMTP, once a sending mailbox exists.

04 Operations

O1No continuous integration, linting or type checking

High
measured.github/ ruff.toml pyproject.toml mypy.ini .pre-commit-config.yaml all absent

214 tests exist and run when somebody remembers. Nothing runs them on a change. This is the class of gap that let a README full of real control bytes be committed unnoticed, and that let three tests quietly make live API calls and write to the production database for as long as they did.

Fix A workflow that runs the suite, ruff, and the contract checker. The single highest-leverage item in this section.

O2Health check does not check anything

Medium

/api/health returns ok if the process is running. It does not touch the database, confirm the master workbook is readable, or report whether the configured reader can be reached. A monitor watching it would have seen green throughout every failure in this document.

Fix A readiness check that opens the database, stats the master workbook, and reports the effective reader — separate from liveness.

O3Both servers are development servers

Medium

The frontend is Python's ThreadingHTTPServer — adequate, and only after a fix for a single-threaded stall that made the app look broken. Neither process has a supervisor: nothing restarts them on failure or on boot, which is why "is it still running?" has been a recurring question.

Fix nginx or Caddy for the static files, and a service manager for the API. TLS lands in the same change.

O4The archive grows unbounded

Low

Every posted row copies its original into data/archive/ and nothing prunes it. Correct for an audit trail; worth a retention decision alongside D4, and it makes D1 more pressing rather than less.

05 The browser

F12,591 lines of JavaScript with no tests at all

High

Every one of the 214 tests is backend. The interface is verified by hand, plus a static check that each element the script reaches for exists and each route has a renderer.

Three separate bugs reached the user through exactly this gap: a response shape the page could not consume, a stalled asset that rendered as an empty sign-in card, and a stale banner contradicting the one beside it. None was reachable from the backend suite.

Fix Browser-driven tests over the real journeys — sign in, upload, review, post. The contract checker in backend/tools/ covers API shape only.

F2Progress is polled, once a second, per document

Medium

The Processing screen polls each document's progress every second for up to ten minutes. For an eighteen-invoice print run that is eighteen requests a second, each one loading and parsing the queue (see A2). It works, and it scales badly in exactly the case it exists for.

Fix One batch progress endpoint, or server-sent events.

F3No accessibility pass

Medium

Status is never carried by colour alone — every pill pairs a colour with an icon and a word, which is the hard part and it was done. But nothing has been checked with a screen reader, there is no skip link, dynamic regions are not announced, and focus is not managed when a screen swaps.

F4Confirmations use native dialogs

Low

Posting an override, deleting a person, and copying a reset link all use confirm() and prompt(). They block the page, cannot be styled, and the reset link in particular deserves better than a browser prompt box.

F5No build step

Low

Deliberate, and mostly a virtue: no toolchain to maintain, nothing to go stale. The cost is no minification, no cache-busting on deploy, and one 2,591-line file. Worth revisiting only if the file keeps growing.

06 The GST domain

What the system models today is the four registers in the client's workbook, done carefully. These are real filing situations it has no representation for — each would produce a wrong row rather than an error.

Not modelledWhat happens todaySeverity
Exports, SEZ supplies, supplies under LUT Treated as ordinary inter-state IGST. Zero-rated supply has no representation. High
Nil-rated, exempt and non-GST supplies A zero rate reads as a missing rate and blocks the document. High
Credit note linked to its original invoice Notes are posted standalone; GSTR-1 wants the original reference. High
Multiple tax rates on one invoice A single rate per document. A mixed-rate invoice reconciles wrongly. High
e-invoice IRN and QR Not extracted or stored. Mandatory above the turnover threshold. Medium
Amendments (B2BA, CDNA) No concept of amending a filed row. Un-post and re-post is not an amendment. Medium
Advances and their adjustment Not represented. Medium
HSN-wise summary One HSN per document; GSTR-1 requires an HSN summary table. Medium
TDS / TCS Not represented. Low
Import of goods and services Bill of entry has no place; RCM on imported services is not distinguished. Low

G1The GSTR-1 reconciliation block covers only rows 8–50

High

Rows 75–80 of the client's own sheet are built from a hand-written list of references covering rows 8 to 50. Rows 51–71 fall outside it. This is pre-existing in the workbook and it is their tax logic, so the application deliberately does not rewrite it.

It needs a decision before the register grows past row 50 in a live month, and the application will not warn when that happens.

G2Opening credit is not carried forward

Medium

A new period starts with input-credit carry-forward at zero and the screen says so. The correct figure is the previous return's closing balance, which the application already holds once that period exists. Today it is typed in by hand, or forgotten.

G3Single tenant

Low

The company profile is a constant in config.py. Every classification decision is made relative to it. If this workbook format is reused across clients, that becomes per-tenant configuration and touches the data model, not just a setting.

07 What to do next

Ordered by consequence, not effort.

01

Close the three blockers you can close today

Set signup back to approval (one click). Back up data/ (half an hour). Resolve the Gemini tier — enable billing or switch provider (one line). None needs a code change from me.

02

Continuous integration

Everything below this line is easier to do safely once a change runs 214 tests and the contract checker automatically. It is also the gap that let several of the others survive unnoticed.

03

Typed responses and SQL-side filtering

A1 and A2 together. Response models make the contract enforceable; moving filtering into SQL removes the half-second that is coming. Both are mechanical.

04

Deploy properly, once

Reverse proxy, TLS, security headers, a service manager, persistent rate limiting. S2, S4, S5 and O3 are one afternoon if done together and four separate jobs if not.

05

Decide the GST scope

The domain table is the one part of this that is a product question rather than an engineering one. Zero-rated supplies, mixed rates and credit-note linkage are the three that would produce a wrong filing rather than a missing feature — worth confirming against what this client actually issues.

06

Browser tests

Three user-visible bugs came through F1. The backend suite cannot see that class at all, and hand-checking has already proved unreliable.

08 What is already solid

A register of gaps reads worse than the system is. For balance, these were checked and hold.

  • The tax arithmetic. Pinned against the client's own figures — ₹439.30 CGST/SGST, ₹1,080 IGST on the Waymiro bill, the ₹6,16,509 opening credit.
  • The source workbook is never written to. Each period is copied from the master; only the copy is appended.
  • Posted rows carry the sheet's own formulas, so they recalculate in Excel like a row a person typed.
  • Registers grow correctly past their template rows, with SUM ranges rewritten and Tax Payable references repointed.
  • Duplicates are caught by reading the register back, not by trusting the queue — and now at upload time too.
  • A print run splits by invoice number, not page count, so an invoice spilling onto a second page stays whole.
  • Passwords are scrypt-hashed; only session token hashes are stored. A stolen database is not a set of live sessions.
  • Every route states its own guard, and administrator actions are separated from user ones.
  • The audit trail names who posted each row, including who overrode a failed check.
  • The reader reports what actually ran, not what was configured — and stops reporting it when the configuration changes.
  • Two backends cannot share a data directory. Enforced by the OS, and it has fired twice for real.
  • Register reads are cached on the workbook's mtime, so a row typed in Excel still appears.
Every measurement in this document was taken from the running system or the real data, not estimated: queue parse timings against a 357-document database, endpoint and guard counts from the source, header and configuration checks against the live servers. Two things were not assessed: the extraction accuracy of the Gemini reader against a broad sample of vendor layouts, and the interface under a screen reader.
