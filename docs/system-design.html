What the system does

A small business receives invoices as PDFs and must transcribe each one into a GST workbook — the right register, the right tax split, the right period. That transcription is mechanical, repetitive and easy to get subtly wrong.

This system reads the PDF, works out the GST treatment, checks its own answer against four rules, and writes a row into the client's actual Excel workbook — the same file, the same sheets, the same formula idioms, so a person opening it cannot tell which rows were typed by hand.

What it deliberately does not do is file anything or decide anything contestable. Every row reaches the workbook because a person pressed Post, and anything the system is unsure about stops and says so.

The four checks that can stop a document

CheckWhat it asksWhy it blocks
GSTIN formatIs each party's GSTIN structurally valid?A malformed GSTIN makes the return unfileable.
Tax reconciliationDoes taxable value × rate equal the tax the invoice printed?A mismatch means the reading is wrong, or the invoice is.
Statutory rateIs the rate one GST actually levies?A rate like 13% is a misread decimal, not a real rate.
DuplicateIs this invoice number already posted in this period?A duplicated row overstates liability or credit.

The workbook's own idiom

A posted row carries the same formula patterns as the rows a person typed, and the sheet's own number formats. When a register grows past its totals row, the totals row is moved down and every Tax Payable formula that pointed at the old position is repointed — openpyxl does not adjust formulas when rows are inserted, so the system does it explicitly.

Architecture

Two containers, a file share, and a database that cannot live on it.

Exactly one replica, permanently

This is a correctness constraint, not a cost saving. Two processes appending to the same register would each write at what it believed was the first free row, and the second save would win — a silently lost tax record. The application takes a kernel lock on its data directory so a second process fails loudly rather than corrupting quietly, and the deployment caps replicas at one.

Design decisions

The choices that shaped the system, and the reasoning that is easy to lose.

Write into the client's own workbookworkbook.py

Not a new file, not a CSV export. The accountant already has a workbook with formulas, formats and a Tax Payable sheet that nets everything off. Producing a different artefact would mean somebody re-typing from it.

Never post automaticallypipeline.confirm

Even a document that passes every check waits at Ready. The system's judgement about an invoice is good enough to prepare a row and not good enough to file one.

Recompute the tax rather than trust itgst/rules.py

The reader extracts the printed figures; the rules derive what they should be. Agreement is evidence; disagreement stops the document. A reader that simply copied numbers could not catch its own misreadings.

Read offline when there is no modelextract/heuristic.py

Without an API key the system parses the text layer itself, with OCR for scans. It never guesses: anything unreadable stays empty and the document goes to Quick Review rather than being auto-confirmed.

Back up before postingbackup.py

Posting is the one irreversible step, so a verified archive is taken first — rate-limited to one an hour, because clearing a morning's queue is thirty posts and thirty archives buy no more safety than the first.

Save the register by replacing itworkbook._save

The new workbook is written beside the old one and renamed into place. A rename is atomic, so a process that dies mid-save leaves one version or the other — never half a register.

Known limits

Stated rather than discovered later.

LimitConsequence
Cold startThe first request after an idle spell takes ten to twenty seconds. That is what keeps the hosting free.
Mirror windowAn ungraceful container kill loses up to two minutes of queue and audit changes. Filings are unaffected.
Single instanceNo redundancy; a restart is a brief outage. Inherent to writing one shared workbook.
Reader qualityRunning offline, extraction is materially weaker than the LLM path and more rows stop at review.
GST scopeZero-rated supplies, mixed-rate invoices and credit-note linkage are not modelled yet.
No stagingA bad image reaches the only environment. Images are tagged per commit, so rollback means pointing at a tag.
