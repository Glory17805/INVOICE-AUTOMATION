Needs your action — not a code issue

The Anthropic account currently returns credit balance too low, so every invoice is being read by the offline parser right now. That parser cannot read scans or photographs at all, and gives text-layer PDFs a simpler read worth checking.

The application handles this correctly and now says so plainly on screen. But the system is running in its degraded mode until the account is topped up, and no change to the code will alter that.

01 Defects found and fixed

Two were live in the product. One made the documentation unusable. One removed a working feature. Nothing in the GST arithmetic was altered — every figure the suite pins against the client's own workbook is unchanged.

1.1Output tax overstated on hand-typed inter-state sales

Fixed

Severity High — wrong tax figures on a screen an accountant reads and files from.

_gstr1_amounts re-derives amounts from rows already sitting in GSTR‑1. It inferred the entire CGST/SGST-vs-IGST split from whether column K held a formula or a literal number: 

if _is_formula(igst_raw):   igst = taxable * rate;  cgst = sgst = 0
else:                       igst = number(K);       cgst = sgst = taxable * rate / 2

Rows this application posts always carry formulas, so the literal branch was never exercised by a test. But the client has kept these sheets by hand for years and will keep doing so alongside the app — and a row typed into Excel carries plain numbers, not formulas.

Reproduced against a copy of the real May‑26 workbook. An inter-state sale, taxable ₹10,000 at 18%, IGST ₹1,800 typed into K, with L and M left blank:

What the sheet says vs. what the app read
SourceIGSTCGSTSGSTTotal
On the sheet1,800.000.000.0011,800.00
Read back as1,800.00900.00900.0013,600.00
After the fix1,800.000.000.0011,800.00

It invented ₹1,800 of tax that is not on the sheet. Because the tax position sums GSTR‑1 through the same function, the error reached the Tax position screen as well as the Registers display.

The fix. K, L and M are each evaluated on their own terms — resolving the sheet's own idioms (=I*J, =J*I/2, =L{row}) and taking literals at face value. Template rows and posted rows evaluate exactly as before, so every pinned figure holds. Four regression tests cover the hand-typed inter-state case, the hand-typed intra-state case, both formula idioms, and an unrecognisable formula, which scores zero rather than guessing.

1.2The header claimed Claude was reading when it was not

Fixed

Severity Medium — silently misrepresents how the work was done.

The API reported the configured reader: holding an API key made the header say “Claude reader” regardless of whether Claude ever answered. Found live — the key returns HTTP 400, credit balance too low, the offline fallback correctly took over, and nothing in the interface said so.

Now the API carries the reader that actually ran alongside the one configured, taken from the most recent document read. The header gained a third state, Claude unavailable, and a banner above every screen explains the consequence.

1.3Every path in the README was wrong

Fixed

The README held five real control bytes where literal escape text belonged — 0x08 for \b, 0x0c for \f, a stray 0x0d. Readers were told to cd d:\IRA\gst-automation​ackend and to run .​un-all.ps1. Every quoted path was uncopyable. A scan of all 37 source files confirms the README was the only one affected.

1.4The watch-folder button had been dropped

Restored

The interface rewrite removed Check watch folder, while the endpoint behind it and the README's description of it as the email-intake stand-in both remained. The only non-upload intake route had no way to trigger it.

02 Gaps closed

Things that were fine until the day they would not have been.

2.1Two processes could silently destroy tax records

Closed

Severity High — unrecoverable loss of a filed record, with no error raised.

Workbook writes were serialised with a thread lock — correct within one process, worth nothing across two. Posting a row is read-the-register, pick-the-next-free-line, write, save. Two backends on the same data directory would interleave those steps and the second save would drop the first one's row. That was one --workers 2 away.

The backend now takes an exclusive kernel lock on its data directory at startup. A second process refuses to start: 

AlreadyRunning: Another backend is already using
D:\IRA\gst-automation\backend\data (held by pid 15812).
Only one process may write these workbooks: a second one would
silently overwrite rows the first has posted.

The lock is held by an open file handle, so the OS releases it on exit — crash or kill included. There is no stale lock file to clear by hand.

2.2No authentication on any endpoint

Closed

Every route was open, including workbook download and the original invoice files. An optional shared secret is now required on every route but the health probe, compared in constant time, accepted as a header or bearer token and refused in a query string — query strings reach browser history, proxy logs and referrer headers. It is off by default, which is right for one machine, and startup logs a warning when off rather than leaving that silent.

Two supporting changes were needed:

  • CORS is registered outside the key check, so a 401 still carries its origin header and the browser reports the real status instead of an opaque CORS failure.
  • The document viewer and workbook download now fetch bytes as blobs. An auth header cannot ride on an <iframe src> or a download link — the browser issues those itself and attaches nothing.

What this is not. One key for the whole deployment, readable by anyone who can load the frontend. It draws a boundary around the network, not around a person. See 4.2.

2.3Four smaller gaps

Closed
  • No version control. The tree was not a git repository despite carrying a .gitignore. Initialised, with the pre-existing state committed as a baseline before any change. The live API key is correctly excluded.
  • Unbounded uploads. Now capped, checked against the declared length before the body is read.
  • Dependencies could jump a major version silently. anthropic>=0.40 resolved to 1.0.0 on a fresh install with nothing to say so. All now carry an upper bound below the next major.
  • Deprecated startup hook. Migrated to the lifespan context manager, which also gives the instance lock a correct release on shutdown.

03 Performance and structure

3.1Uploading a print run held the request open for minutes

Improved

Upload ran the whole pipeline inline: one model call per invoice, eighteen for a print run, inside a single HTTP request. A browser sat on a spinner with nothing to show, and any timeout threw away the response to work that had in fact happened.

Capture and reading are now separate. Measured: 78 ms to respond, with documents returned unread; the page then polls them out of their pending state so the inbox fills in as each invoice lands. Failures in the background task are recorded on the document, because a traceback on a detached task is seen by nobody.

3.2Every screen re-parsed the whole workbook

Improved

One visit to Registers re-parsed the .xlsx four times, then Tax position did it again, against a file that had not changed. Reads are now cached against the workbook's modification time, with writes evicting explicitly so correctness does not rest on timestamp resolution. Because the key is the file's own mtime, a row typed directly into the workbook in Excel is still picked up — which a naive cache would have masked. Suite runtime fell from ~90s to ~70s.

3.3The queue rewrote a whole file on every change

Improved

store.json was parsed in full on every read and rewritten in full on every write, so touching one document cost time proportional to how many had ever arrived. A write was also a whole-file replace — fine until the process dies mid-replace.

Replaced with SQLite: one file, standard library, no service to run, real transactions, indexes on the columns the inbox filters by. The store's interface is unchanged, so nothing above it knows the difference. An existing store.json is imported on first use and renamed, not deleted. Verified against the live 18-document queue: identical ids, blobs identical including history.

04 Recommended next

Ordered by what would matter most, not by effort. The numbering is the recommended sequence.

01

Restore Claude extraction

Operational, and blocking quality today. Until the account is topped up the system runs on the offline parser, which cannot read scans at all. Nothing in the code will fix this.

02

Per-user authentication and an attribution trail

The current key identifies a deployment, not a person. For a filing system, “who posted this row?” is a question an auditor may reasonably ask, and today there is no answer.

Worth doing as one piece: accounts, a token per user, and a posted_by field carried onto the document history and the archive path. That also attributes the override action — posting a document that failed validation — which is the most audit-sensitive thing the system permits.

03

Rate-limit the key

A shared secret on an exposed port invites guessing, and nothing currently slows that down or records the attempt. A per-IP failure counter with a backoff and a logged warning is proportionate. Pairs naturally with the item above.

04

Terminate TLS

The key and every invoice travel in clear text. On one machine that is fine; across a network it is not, since the key is in a header on every request. Do it at a reverse proxy, not in the application.

05

Back up the data directory

It holds the per-period workbooks, the archived originals that constitute the audit trail, and the queue. It is gitignored, correctly, and nothing backs it up. The master workbook can re-seed structure but not posted rows.

06

Carry the opening credit forward automatically

A new period starts with input-credit carry-forward at zero and says so. The correct figure is the previous return's closing balance, which the application already holds. Computing it — behind an explicit confirmation, since it is a filed figure — removes a manual step that is easy to forget and expensive to get wrong.

07

Direct email intake

Intake is a watch folder driven by a button. An IMAP or Graph connector polling the mailbox invoices actually arrive in would close the last manual step in capture. Small, and gated only on knowing which mailbox.

08

Decide on the GSTR-1 reconciliation block

Rows 75–80 are built from a hand-written list of references covering rows 8–50, so rows 51–71 fall outside it. Pre-existing in the client's workbook and their tax logic, so the app deliberately does not rewrite it — but it needs a decision before the register grows past row 50 in a live month.

09

Plan for more than one writer

The instance lock makes today's limit explicit and safe, but it is still a limit. Serving concurrent users means moving workbook writes behind a single queue consumer, not adding worker processes. Nothing needs it yet; the constraint should be understood before someone reaches for --workers.

10

Smaller items

  • No frontend tests. All 135 are backend; the interface is checked by hand.
  • No CI. The suite runs when someone remembers — which is the class of problem that let 1.3 through.
  • Secrets in plaintext. Fine on one trusted machine; a secret store is the answer on a server.
  • Duplicate detection is per-period. The same invoice number in two months is not flagged. Probably right, but it is an assumption worth stating.
  • Single tenant. The company profile is hard-coded. If the workbook format is reused across clients this becomes per-tenant configuration.
  • openpyxl drops charts and pivot tables. This workbook has neither, so nothing is lost today. Re-check if it gains them.
